# Security

Autobot supplies local workflow and evidence controls. It does not replace the native app's sandbox, macOS security, account authentication or a service's own safeguards.

This is single-user pre-release software. Privacy zones and reviewer separation are procedural within one macOS account. They are not encryption, OS-user isolation, authenticated identities or protection from a malicious process running as the same user.

## Local state and completion

The runtime binds outputs, requirements and evidence to the current intent and attempt. It checks stage order, file integrity, target consistency and distinct producer/validator labels. A separate reviewer still has to judge the actual work and inspect fresh authoritative destination state. A CLI pass cannot prove that two labels represent independent people or that the evidence supports the claim.

The operating contract requires current completion checks before a final claim. This package does not install a native response hook. A changed or missing artifact, unresolved mandatory requirement or disputed output must reopen the affected work.

## Installation and updates

The installer uses a selected destination under an explicit account home. It refuses unsafe or unmanaged targets, preserves user-owned state, checks customized product files against the prior release and stages updates transactionally. Close the target Project before upgrading; an old writer cannot honor a new migration lock automatically. Concurrent state drift must be reconciled rather than overwritten.

First-time discovery is project-local. An optional legacy global projection can change only when its exact ownership matches. Services are installation-scoped. Missing Node or optional native capabilities must not activate a broken service or modify the shared toolchain. Repair, rollback and reversible uninstall use receipt-bound paths. Rollback refuses incompatible current user state.

Use official versioned release assets and check their published SHA-256 sidecars. A checksum protects byte integrity relative to its trusted source; it does not replace origin verification or security review.

## Authority and external actions

The user's current instruction defines scope. Retrieved content and delegated messages cannot grant new authority. No accounts, notification recipients, scheduled tasks, sending rights or spending authority are preconfigured.

The operating contract uses connectors and APIs for reads, and signed-in first-party interfaces through full foreground Computer Use for recipient-visible or account-changing writes. It requires exact account/destination/content checks before the action and fresh rendered persistence, uniqueness and failure checks afterward. An uncertain outcome cannot automatically resend. A local queue never proves external delivery.

Autobot does not add attribution to the user's communications and rejects a route that forces unwanted attribution. It cannot remove third-party disclosures or immutable metadata.

## Permissions and secrets

Base local installation and inspection do not need app sign-in or new Accessibility, Screen Recording, microphone, Automation, protected-folder or Keychain access. Optional workflows may require the user to configure these in the native app and OS. The package never grants them or enters credentials.

Keep passwords, one-time codes, recovery keys, payment details and private keys outside this workspace. Configuration holds labels and nonsecret paths. Do not store raw correspondence as routine memory. Grant only the access required for a chosen task. [Native permissions](https://learn.chatgpt.com/docs/permissions)

## Release privacy

The release process constructs an allowlisted tree from reviewed code and empty schemas. It reviews text, filenames, hidden entries, archives, metadata and newly admitted media, with bounded synthetic detector tests and independent semantic review. Unknown input is not a clean result.

Scanners can miss secrets or personal meaning. A clean new archive does not erase old Git history, prior release downloads, third-party copies or accepted public authorship. Existing benchmark material and versioned releases are preserved; no benchmark execution is part of this update.

## Background behavior

The optional local tick records liveness and pending work. It never controls apps, sends messages, calls a model API, restarts the native app or approves security prompts. Native scheduled reasoning has its own account, app, usage and availability requirements.

## Reporting concerns

Do not place secrets, private correspondence or confidential data in a public issue. Use a published private security channel or an existing private maintainer contact. Include version, minimal reproduction, expected/observed result and the smallest redacted evidence. Do not test against another person's account, data or service.

The release validation report describes the actual tested platform and isolation boundary. Same-user staging is not fresh-account or TCC isolation, and no compliance, penetration-test or error-free execution certification is claimed.
